# Identity and account lifecycle — M3A

Implemented 2026-11-20: Better Auth **1.7.27**, native D1/Kysely adapter, email OTP registration/sign-in/recovery, database sessions and `/account/`. Production email uses Cloudflare Email Service from `accounts@cheapseggs.com`; no third-party auth/email subscription. Real age assurance and restricted content remain closed. Deployment evidence lives in [Launch report](LAUNCH_REPORT.md).

## Evaluation and dependency policy

Better Auth is maintained and framework-independent. Version 1.7.27 supports D1 directly: no Drizzle dependency or handwritten auth schema is required. `createIdentity` is shared with `scripts/generate-auth-schema.ts`; the pinned library's `getMigrations(...).compileMigrations()` generated `0003_better_auth.sql`. CI checks schema drift against that configuration. Subsequent changes require append-only migrations. `nodejs_compat` supplies the library's supported runtime imports. The compiled Worker is exercised against workerd and D1, rather than relying on Node tests alone. D1 does not support interactive transactions: framework operations use its non-transactional adapter, with single-statement conditional OTP consumption and SQL triggers for atomic domain creation/deletion.

Reviewed [official advisories](https://github.com/better-auth/better-auth/security/advisories), latest supported release and `npm audit` on 2026-11-20. The [email OTP race/address-binding advisory](https://github.com/better-auth/better-auth/security/advisories/GHSA-2f9c-7xj7-gh55) and [email-change advisory](https://github.com/better-auth/better-auth/security/advisories/GHSA-hwq2-v29r-p69r) were patched in 1.7.16; this integration uses 1.7.27. OAuth, linking, admin, SCIM, SSO, Expo and Electron surfaces are not enabled. No claim that an audit proves absence of vulnerabilities. Only the latest supported stable auth version should be used; review advisories and update promptly, without scheduled CI.

[Better Auth database documentation](https://better-auth.com/docs/concepts/database) documents native D1 migrations. [Session documentation](https://better-auth.com/docs/concepts/session-management) describes freshness and cookie caching. Auth.js remains viable with its D1 adapter, but introduces a different integration without a demonstrated benefit here. Managed Clerk would add vendor/privacy/price dependencies. Better Auth reuses the existing architecture and keeps account state in D1.

## Registration, return and recovery

The same maintained [email OTP plugin](https://better-auth.com/docs/plugins/email-otp) verifies inbox ownership and creates a new independent account if needed. No legal name, DOB, image, phone, ID document or selfie is requested. An explicit 18+ declaration is required on both code request and submission; it is stored separately from identity and expires after one year. It is not independently verified age or legal identity.

Codes have eight digits, expire after ten minutes, allow five failed attempts and are consumed once by the framework's atomic verification. They are encrypted by the framework at rest, never logged or exposed by a read endpoint. GET does not consume a code or create a session, so email scanners cannot authenticate users. No magic-link redirect/callback URL is accepted. Production secrets have no fallback. The UI discloses that the site appears in email/history and inbox compromise compromises recovery.

Recovery: request a fresh code and check “Recover my account”; successful verification revokes all other sessions. Normal sign-in supports multiple devices and replaces this browser's previous session. No partner/staff/security-question bypass. Losing inbox access cannot be repaired through intimate answers. Email changes, passwords, OAuth and passkeys are deliberately unsupported; they are not required for this email-only foundation and must not appear as working settings.

## Session, CSRF and abuse controls

- Framework-generated opaque sessions in D1. `__Host-cheapseggs.session`, Secure, HttpOnly, SameSite=Lax, Path=/, no Domain attribute. Local HTTP uses a separate development cookie. No browser-storage bearer tokens; framework JSON tokens are removed from public responses.
- Seven-day absolute lifetime, refresh disabled, 24-hour idle limit checked against authoritative D1 on each account operation. The application updates only `updatedAt`; all framework dates in SQLite are ISO strings. Five-minute freshness is required for deletion. No cookie session cache, KV authorization or replica session reads.
- List sessions by opaque record ID and timestamps, with no session token, IP or user-agent. Per-device/all-device revocation uses the framework with owner-scoped lookup. No client-selected account ID. Application routes reject a revoked/missing/deletion-marked identity.
- Mutations require exact canonical Origin, same-origin Fetch Metadata when present, JSON and the `X-CheapSeggs-Action: account` header. This reviewed non-simple-request pattern plus no cross-origin CORS replaces a synchronizer-token scheme. Framework CSRF remains enabled. 4 KiB bodies and strict bounded schemas; fixed redirects only.
- Atomic D1 counters: 180 account requests/network/15 min, three code sends/address/15 min, ten sends/network/15 min, fifteen submissions/address/15 min. The framework additionally caps wrong attempts per challenge. Counter keys are HMAC fingerprints with separate scope/window; no raw IP or email in the abuse table. Fixed windows may permit adjacent-window bursts. Unknown production client address and database errors fail closed.
- Global send caps: 100/day and 1,000/calendar month. Failed sends consume capacity. Only one recipient and the fixed sender are accepted. No marketing, email body logs, tracking links or external images. Cloudflare may retain its own delivery/recipient metadata; do not promise anonymous email. Email providers and shared inboxes remain trusted boundaries.

## Guest transition and deletion

The wheel still uses an in-memory guest nonce and no auth requirement. Its Account link explicitly clears/revokes that guest session before navigation. No settings, exclusions, results or activity history are imported, attached or merged into an account. Returning to guest play creates a new nonce. Directly navigating away leaves unreachable guest rows until their existing 24h TTL/lazy purge. Account cookies are ignored by guest selection.

Deletion requires typing DELETE and a session created within five minutes. Better Auth removes the identity and sessions; a database trigger deletes its domain user/declarations/category approvals and pending email challenge within the same user-delete statement. No commercial/private records are created by M3A. Any future such features must extend the deletion design before activation. A minimal random subject-ID deletion ledger remains, without email, interest or history. Live rows disappear immediately; Cloudflare D1 backups age out within the account's 30-day Time Travel window. No extra backup service exists.

**Restore rule:** never serve a restored database directly. Export the current deletion ledger separately before restore, restore into an isolated target, replay those deletions and revoke every restored session/challenge before routing traffic. If the latest ledger is unavailable, recovery remains offline until its deletion obligations are resolved. There is no automated backup-restore workflow or claim of cryptographic erasure. See [Deployment](DEPLOYMENT.md).

## Verification

`npm run check` includes framework schema drift, Node/SQLite account tests and compiled workerd/D1 tests with an intercepted local mail transport. Coverage includes replay/concurrent use, attempts/expiry, cross-origin requests, declaration withdrawal, foreign-session revocation, recovery, idle/fresh access, deletion and disabled assurance. Browser tests cover unavailable email, account forms, explicit confirmations, accessibility and unchanged guest behavior. Tests never send real email. Final live verification checks release identity and safe behavior; real inbox delivery must be distinguished from provider acceptance.
